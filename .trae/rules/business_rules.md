# 业务逻辑规则

## 1. 用户管理

### 1.1 注册流程
1. 验证邮箱格式和密码强度
2. 密码使用bcrypt进行哈希存储
3. 生成JWT访问令牌
4. 返回用户信息和令牌

### 1.2 认证机制
- 所有需要认证的API请求必须在Authorization头中包含有效的JWT令牌
- 令牌过期时间：30分钟
- 令牌无效或过期时返回401错误

## 2. 内容管理

### 2.1 收藏管理

#### 前端实现
- 收藏列表使用`loadFavorites`方法通过`/api/users/me/favorites`接口获取数据
- 收藏数据映射为包含`id`、`content_id`、`content`对象和`created_at`的对象数组
- `content`对象包含`id`、`title`、`category`等字段，用于前端显示收藏内容信息
- 收藏列表模板使用`v-for`循环遍历`favorites`数组生成收藏项
- 收藏标题必须使用`<router-link>`组件实现链接功能
- 链接路径根据`category`动态生成：
  - `agent`类型跳转到`/agent/${item.content_id}`
  - 其他类型跳转到`/article/${item.content_id}`
- 收藏项包含：标题、摘要、分类、日期和"取消收藏"按钮

#### 链接样式规范
- 收藏标题链接使用`.favorite-title-link`类名
- 基础样式：链接颜色跟随主题色，字重加粗，无下划线
- 悬停效果：颜色加深，显示下划线，出现轻微上浮效果
- 下划线动画：从左向右平滑过渡，增强交互反馈

#### 后端实现
- 收藏API路径：`GET /api/users/me/favorites`
- 支持分页参数：`page`（页码）和`page_size`（每页数量，最大50）
- 返回数据结构：
  ```json
  {
    "status": "success",
    "data": [
      {
        "id": "收藏记录ID",
        "content_id": "内容ID",
        "content": {
          "id": "内容ID",
          "title": "标题",
          "category": "分类",
          "summary": "摘要",
          ...
        },
        "created_at": "收藏时间"
      }
    ],
    "total": "总数"
  }
  ```
- 取消收藏API：`DELETE /api/content/{content_id}/collect`

### 2.2 文章管理

- 文章支持富文本格式
- 文章可分类和标签化

- 购买后的智能体支持下载

### 2.4 页面显示规则

#### 首页
- 文章列表固定显示4个卡片
- 智能体列表固定显示2个卡片
- 无论分类页面如何操作，首页显示数量始终保持不变

#### 文章分类页面

- 支持"加载更多"功能，每次加载4个文章卡片

#### 智能体分类页面
- 初始显示6个智能体卡片
- 支持"加载更多"功能，每次加载2个智能体卡片
- 显示数量与首页无关，独立管理

#### 注意事项
- 此显示规则为核心业务逻辑，未经用户明确同意不得修改
- 首页与分类页面的显示数量必须严格分离，不得互相影响
- 修改任何显示逻辑前必须与用户沟通并获得批准

### 2.5 路由参数筛选与时序问题

#### 问题场景
当使用URL参数（如`/articles?category=孕期营养`）进行内容筛选时，需要确保数据加载完成后再处理筛选逻辑

#### 时序问题
Vue的`watch`监听器使用`immediate: true`时会立即执行，但如果依赖的动态数据（如从API获取的分类列表）尚未生成，会导致筛选失败

#### 解决方案
在`onMounted`钩子中，**确保先加载数据并生成分类列表**，然后再检查URL参数并设置筛选状态

#### 代码模式
```javascript
onMounted(async () => {
  loading.value = true
  try {
    await contentStore.fetchLatestArticles()
    // 数据加载完成后动态生成分类列表
    updateCategories()
    
    // 分类列表生成后，检查URL参数并设置筛选状态
    const urlCategory = route.query.category
    if (urlCategory) {
      const category = categories.value.find(c => c.name === urlCategory)
      if (category) {
        activeCategory.value = category.id
      }
    }
  } catch (error) {
    console.error('加载内容失败:', error)
  } finally {
    loading.value = false
  }
})
```

#### 关键点
1. 先执行数据加载和分类列表生成
2. 再检查URL参数并设置activeCategory状态
3. 确保`categories`数组已填充后再进行查找匹配

#### 适用场景
所有需要从URL参数读取并同步页面状态的场景（如分类筛选、搜索关键词等）

### 2.6 小红书风格文章格式规范（重要）

所有生成的文章必须严格遵循以下格式要求，确保内容符合母婴群体的阅读习惯和审美偏好

#### 2.6.1 标题规范

**格式要求**：
- 标题必须使用中文标点符号（，。！？：；""）
- 标题开头必须带emoji表情符号（如👶、💕、🍼、👩等）
- 标题长度建议在15-35字之间
- 标题应使用疑问句、感叹句或陈述句，增强吸引力
- 标题应体现实用性和价值感，如"必看""攻略""指南""技巧"等

**示例**：
- ✅「👶 新生儿黄疸怎么办？新手妈妈必看的应对指南」
- ✅「💕 宝宝哭闹不止？快速安抚方法大公开」
- ❌「新生儿黄疸的医学知识和护理方法」（无emoji、过于正式）

#### 2.6.2 内容结构规范

**整体结构**：
- 采用「开头引入 → 问题分析 → 解决方案 → 注意事项 → 总结」的五段式结构
- 总字数控制在800-1200字之间
- 内容层次清晰，逻辑连贯

**段落标题规范**：
- 使用HTML `<h3>` 标签作为段落标题
- 标题必须以emoji开头，增强视觉吸引力
- 每篇文章包含3-6个段落标题
- 标题之间要有逻辑递进关系

**段落内容规范**：
- 使用HTML `<p>` 标签作为段落容器
- 内容语言口语化、亲和自然，像和朋友聊天
- 适当使用「姐妹们」「妈妈们」「大家」等称呼
- 适当使用emoji表情符号增加亲和力

**列表规范**：
- 使用HTML `<ul>` 和 `<li>` 标签创建无序列表
- 每个列表项使用 `<li><strong>标题</strong>：内容</li>` 格式
- 列表项控制在3-7个之间
- 列表用于呈现步骤、方法、注意事项等内容

**示例结构**：
```html
<h3>👶 标题emoji + 简短描述性文字</h3>
<p>引入段落，用2-3句话引入话题，建立共鸣。</p>
<p>展开说明，提供背景信息或问题分析。</p>
<h3>💡 具体解决方法或步骤</h3>
<p>详细说明方法或步骤，语言要具体可操作。</p>
<ul>
  <li><strong>第一步</strong>：具体操作内容</li>
  <li><strong>第二步</strong>：具体操作内容</li>
  <li><strong>第三步</strong>：具体操作内容</li>
</ul>
<h3>⚠️ 注意事项或常见误区</h3>
<ul>
  <li><strong>注意事项1</strong>：具体说明</li>
  <li><strong>注意事项2</strong>：具体说明</li>
</ul>
<h3>💕 鼓励性总结</h3>
<p>用温暖鼓励的语言结束文章，增强情感连接。</p>
```

#### 2.6.3 表情符号使用规范

**常用emoji分类**：
- 人物类：👶、👩、🤱、👨‍👩‍👧、👵
- 情绪类：💕、😊、😢、🤔、😉
- 物品类：🍼、🛏️、👶、🧸
- 动作类：💪、💆‍♀️、🧠、👀
- 标记类：✅、❌、💡、⚠️、📊、🔍

**使用原则**：
- 每个段落标题必须带1个emoji
- 每个重点内容前可适当添加emoji
- 全文emoji数量控制在5-15个之间
- 避免在同一段落中连续使用多个emoji

#### 2.6.4 语言风格规范

**语气**：
- 亲切、温暖、像朋友聊天
- 适度使用「呀」「啦」「呢」等语气词
- 避免过于正式、学术化的表达

**人称**：
- 使用第二人称「你」「您」
- 使用「妈妈们」「姐妹们」等群体称呼
- 避免使用「用户」「客户」等商业化称呼

**句式**：
- 适当使用疑问句引发共鸣
- 适当使用感叹句增强情感
- 短句为主，避免长篇大论

**示例对比**：
- ❌「新生儿黄疸是一种常见的生理现象，需要家长注意观察」
- ✅「👶 新手妈妈别慌！黄疸其实没那么可怕」
- ❌「建议产妇在产后多休息，保持良好的饮食习惯」
- ✅「💕 产后恢复是一个漫长的过程，不要急于求成」

#### 2.6.5 内容质量要求

**实用性**：
- 每个建议都要具体可操作
- 提供的方法要有数据或经验支持
- 包含常见问题的解决方案

**真实性**：
- 经验分享要真实可信
- 适当加入个人经历或案例
- 承认局限性，不要夸大效果

**安全性**：
- 医疗健康建议要保守、建议就医
- 产品推荐要客观公正
- 避免传播未经验证的偏方

**完整性**：
- 问题分析要全面
- 解决方案要完整
- 注意事项要详尽

#### 2.6.6 内容生成器集成
- **backend/content_generator.py** 中的 `CONTENT_TEMPLATES` 必须严格遵循上述格式规范
- 任何文章生成脚本（如 `generate_articles.py`、`manual_articles.py`）都必须使用符合小红书风格的模板
- 手动添加文章时必须检查格式是否符合规范
- 使用 `verify_xiaohongshu_format.py` 验证文章格式

#### 2.6.7 格式验证清单
生成或添加文章后，必须检查以下项目：
- [ ] 标题以emoji开头
- [ ] 标题使用中文标点
- [ ] 内容使用HTML标签（`<h3>`、`<p>`、`<ul>`、`<li>`）
- [ ] 每个段落标题都有emoji
- [ ] 语言风格亲切、口语化
- [ ] 使用第二人称「你/您」
- [ ] 包含「妈妈们」「姐妹们」等称呼
- [ ] 字数在800-1200字之间
- [ ] 有明确的结构层次
- [ ] 内容实用、可操作

## 4. 联盟推广系统

### 4.1 推广链接格式
`http://localhost:5173?ref={unique_code}`

### 4.2 佣金规则
- 佣金比例：订单金额的10%
- 结算状态：
  - pending: 待结算
  - paid: 已结算
  - cancelled: 已取消
- 结算周期：每月15日结算上月佣金

### 4.3 跟踪机制
- 记录推广链接的点击次数和来源信息
- 购买转化后自动计算并记录佣金

### 4.4 商品推荐功能（推广位）

#### 4.4.1 推荐位置规则
- **侧边栏推荐**：所有页面（首页、文章列表页、文章详情页）的侧边栏"热门文章"模块下方显示1-2个商品推荐
- **精选好物页面**：整个页面都是商品展示，保持现状
- **禁止位置**：除精选好物页面外，其他所有页面的正文下方禁止放置商品推荐区块

#### 4.4.2 推荐策略
##### 4.4.2.1 首页和文章列表页
- **已登录用户有浏览历史**：基于用户最近浏览的文章进行AI分析，推荐相关商品
- **已登录用户无浏览历史**：返回热门商品（按点击次数排序）
- **未登录用户**：返回随机推荐商品

##### 4.4.2.2 文章详情页
- 基于当前文章内容进行AI分析
- 提取关键词、商品类型、目标人群等信息
- 使用商品匹配器精准匹配相关商品
- AI分析失败时降级为基于分类推荐

#### 4.4.3 商品分类
数据库中的商品分类包括：
- 孕期指南
- 新生照顾
- 幼儿发展
- 亲子互动
- 早期教育
- 营养健康
- 产后恢复
- 育儿用品

#### 4.4.4 API接口
##### 4.4.4.1 基于浏览历史推荐
- 接口路径：`GET /api/products/recommend-by-history`
- 请求参数：
  - `limit`（可选）：推荐数量，默认4
- 响应数据：商品列表
- 认证：可选（支持未登录用户）

##### 4.4.4.2 基于文章内容推荐
- 接口路径：`GET /api/products/recommend-by-content`
- 请求参数：
  - `article_id`（必需）：文章ID
  - `limit`（可选）：推荐数量，默认2
- 响应数据：商品列表

##### 4.4.4.3 基于分类推荐（已废弃）
- 接口路径：`GET /api/products/recommend`
- 请求参数：
  - `category`（必需）：商品分类
  - `limit`（可选）：推荐数量，默认2
- 响应数据：商品列表

#### 4.4.5 前端组件使用
##### 4.4.5.1 侧边栏推荐（首页、文章列表页）
```vue
<ProductRecommendation 
  mode="history"
  :limit="2"
/>
```

##### 4.4.5.2 文章详情页推荐（侧边栏）
```vue
<ProductRecommendation 
  mode="ai"
  :article-id="article.id"
  :limit="2"
/>
```

#### 4.4.6 用户浏览历史跟踪
- 使用ViewHistory模型记录用户浏览的文章
- 记录信息：用户ID、文章ID、浏览时间、会话ID
- 未登录用户使用session_id跟踪
- 已登录用户使用user_id跟踪
- 每个用户对同一文章只记录一次浏览

#### 4.4.7 AI商品匹配逻辑
- 使用DeepSeek AI模型分析文章内容
- 提取关键词、商品类型、目标人群、价格区间等信息
- 使用ProductMatcher进行商品匹配
- 匹配维度：商品名称、描述、分类
- 匹配算法：关键词匹配 + 分类匹配
- AI分析失败时降级为基于分类推荐

#### 4.4.8 注意事项
- 商品图片链接为示例链接，可能无法正常显示，但商品信息应正常显示
- 点击商品会记录点击次数并跳转到购买链接
- AI分析失败时会自动降级为基于分类推荐
- 未登录用户会返回随机推荐商品
- 禁止在正文下方添加商品推荐区块（精选好物页面除外）

## 5. 隐私政策

### 5.1 数据收集规则
隐私政策必须与实际代码实现保持一致，任何涉及数据收集的代码变更都必须同步更新隐私政策。

#### 5.1.1 用户注册信息
- **收集字段**：用户名、邮箱、密码（哈希存储）
- **数据库模型**：User模型（models.py）
- **存储位置**：数据库users表
- **收集目的**：账户创建、身份验证、服务提供
- **收集方式**：用户主动提供

#### 5.1.2 个人资料信息
- **收集字段**：头像URL、性别、生日、个人简介
- **数据库模型**：User模型（models.py）
- **存储位置**：数据库users表
- **收集目的**：个性化服务、用户识别
- **收集方式**：用户主动提供（可选）

#### 5.1.3 宝宝相关信息
- **收集字段**：宝宝姓名、宝宝生日、宝宝性别、宝宝成长里程碑
- **数据库模型**：User模型（models.py）
- **存储位置**：数据库users表
- **收集目的**：提供个性化育儿建议、精准内容推荐
- **收集方式**：用户主动提供（可选）

#### 5.1.4 浏览历史
- **收集字段**：用户ID、文章ID、浏览时间、会话ID
- **数据库模型**：ViewHistory模型（models.py）
- **存储位置**：数据库view_history表
- **收集目的**：用户体验优化、个性化推荐、统计分析
- **收集方式**：自动收集

#### 5.1.5 前端存储
- **存储内容**：用户信息、认证令牌（token）、内容缓存
- **存储位置**：浏览器localStorage
- **收集目的**：保持登录状态、提升用户体验
- **收集方式**：自动收集

### 5.2 隐私政策维护规则

#### 5.2.1 同步更新原则
- 任何涉及数据收集的代码变更都必须同步更新隐私政策
- 新增数据收集字段时，必须在隐私政策中说明
- 删除数据收集字段时，必须在隐私政策中移除
- 修改数据收集目的时，必须在隐私政策中更新

#### 5.2.2 代码变更检查清单
在修改以下代码时，必须检查是否需要更新隐私政策：
- 修改User模型字段
- 修改ViewHistory模型字段
- 修改localStorage存储逻辑
- 新增数据收集功能
- 删除数据收集功能
- 修改数据使用目的

#### 5.2.3 隐私政策更新流程
1. 确认代码变更涉及的数据收集内容
2. 更新PrivacyView.vue中对应的章节
3. 更新business_rules.md中的数据收集规则
4. 测试隐私政策页面显示正常
5. 更新生效日期

### 5.3 数据存储和保留规则

#### 5.3.1 存储地点
- 数据库：PostgreSQL（生产环境）
- 存储位置：中华人民共和国境内
- 跨境传输：需要安全评估并获得用户单独同意

#### 5.3.2 存储期限
- **账户信息**：在账户存续期间及注销后6个月内
- **浏览记录**：保留12个月
- **订单信息**：保留3年（法律要求的最长期限）
- **客服记录**：保留2年
- **前端缓存**：根据浏览器设置，用户可手动清除

### 5.4 Cookie使用规则

#### 5.4.1 Cookie类型
- **认证Cookie**：保持用户登录状态
- **偏好Cookie**：记住用户设置
- **分析Cookie**：统计分析网站使用情况
- **第三方Cookie**：可能使用的第三方服务Cookie

#### 5.4.2 Cookie管理
- 用户可通过浏览器设置管理或删除Cookie
- 删除Cookie可能影响网站部分功能
- 提供Cookie管理说明文档

### 5.5 数据安全规则

#### 5.5.1 安全措施
- 数据传输加密：使用SSL/TLS加密技术
- 数据存储加密：敏感数据采用加密存储
- 访问控制：严格的权限管理和访问控制
- 安全审计：定期进行安全审计和漏洞扫描
- 员工培训：定期对员工进行隐私和安全培训

#### 5.5.2 数据泄露通知
- 通知时限：72小时内
- 通知内容：安全事件基本情况、影响、处置措施
- 通知方式：邮件、短信、网站公告

### 5.6 用户权利规则

#### 5.6.1 用户权利类型
- **访问权**：查看个人信息
- **更正权**：修改错误信息
- **删除权**：删除个人信息
- **改变授权同意范围**：管理偏好设置
- **注销账户**：随时注销账户

#### 5.6.2 权利行使流程
- **处理时限**：15个工作日
- **申请方式**：邮箱、电话、地址
- **投诉渠道**：内部投诉、外部投诉（网信、公安等）

### 5.7 未成年人保护规则

#### 5.7.1 不主动收集
- 服务主要面向成年人
- 不主动收集未成年人信息

#### 5.7.2 发现处理
- 发现未成年人信息时立即删除
- 监护人可申请查询、更正、删除

### 5.8 敏感信息保护规则

#### 5.8.1 敏感信息定义
- 生物识别信息
- 宗教信仰
- 特定身份
- 医疗健康
- 金融账户
- 行踪轨迹
- 不满十四周岁未成年人的个人信息

#### 5.8.2 特殊保护措施
- 收集前获得明确同意
- 采用加密等安全技术措施
- 限制访问权限
- 定期审查使用情况

### 5.9 第三方服务规则

#### 5.9.1 使用的第三方服务
- 支付服务：支付宝、微信支付等
- 统计分析服务：Google Analytics、百度统计等
- 内容分发：CDN服务提供商

#### 5.9.2 第三方数据处理
- 第三方服务提供商受其各自隐私政策约束
- 建议用户阅读第三方隐私政策
- 不与第三方共享用户信息（服务必需除外）

### 5.10 注意事项

- 隐私政策必须与实际代码实现保持一致
- 任何数据收集相关的代码变更都必须同步更新隐私政策
- 定期审查隐私政策的准确性和完整性
- 如有疑问，建议咨询法律专业人士
